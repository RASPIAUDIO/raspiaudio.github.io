# Voice DSP+ V2 USB Recovery (Beta)

[Install on ZeroCore S3](https://apps.raspiaudio.com/#device=ZeroCoreS3&application=USBRecovery)
| [Read serial status](https://apps.raspiaudio.com/ZeroCoreS3/USBRecovery/status.html)
| [Finish USB update](https://raspiaudio.com/voicedsp/webflasher/?firmware=v2-usb-mono-48k)

No Home Assistant, Wi-Fi setup or XTAG. This replaces the ZeroCore ESP32
application with a temporary SPI loader for Voice DSP+ **V2 only**.

1. Stop playback and disconnect speakers. With power off, fit ZeroCore to the
   V2 40-pin connector. Connect ZeroCore USB data to the PC and install this app.
   Erase the ESP32 during installation to remove an old OTA selection/settings.
2. Close the installer. Disconnect ALL power for ten seconds, then reconnect
   both USB data cables. The ZeroCore automatically loads USB **0.8.9-r4** into
   XMOS RAM. Allow 15 seconds. If ESP32 remains in download mode, press RESET
   once without BOOT. Do not keep resetting a running XMOS.
3. Use the status page if necessary. A successful transfer is not an assertion
   that USB has enumerated. The loader never writes XMOS QSPI.
4. Keep power connected and install the recommended V2 USB upgrade using the
   XMOS web updater. This second step writes persistent firmware.
5. Power off, remove ZeroCore, then boot Voice DSP+ USB alone. Verify standalone
   boot and volume before reconnecting speakers. Recovery reloads RAM at every
   normal ZeroCore reset while it remains attached.

## Limits and verification

This is USB runtime recovery, not blank-board factory provisioning. An existing
compatible XMOS QSPI factory layout is required for a persistent DFU upgrade.
If QSPI is blank/corrupt, use a factory programmer; do not call a temporary RAM
boot a successful permanent repair. No factory-partition write is performed by
this app. Power cycling without the final USB update loses the RAM image.

Bridge 0.1.0 is built from the guarded, hardware-tested factory loader 0.2.2 and
the exact accepted XMOS USB 0.8.9-r4 image. The new combination is compiled and
software-tested, **not yet end-to-end hardware validated**. AEC/filter coefficients
are unchanged. No sounds are generated by the bridge; the USB runtime may restore
saved output/volume, hence speakers should be disconnected during recovery.

The embedded SPI SHA256 is
`4fd9bb38fd1112cd37164d79c35e140971c62503acc95e3a1e235c509115b439`.
`release.json` and `SHA256SUMS` record the ESP32 parts and source hashes.

## Source and build

`source/` is the complete PlatformIO bridge project, including its embedded
XMOS SPI image. Build with PlatformIO Core and `pio run -d source` (Espressif32
6.12.0, Arduino ESP32 2.0.17). The generated firmware is ESP32-S3, DIO, 16 MB.
Flash offsets are recorded in the ESP Web Tools manifest. The bridge uses no
Wi-Fi/API credentials. Our bridge code is MIT; Arduino/framework licenses remain
unchanged (Arduino core LGPL-2.1, Espressif IDF components under their own licenses).
The embedded XMOS binary is not MIT. Its source package and notices are in the
[public V2 USB directory](https://github.com/RASPIAUDIO/Voice-DSP-Plus/tree/V2/USB).

The `factory_*` helper names in source are retained from the proven loader.
They guard bus ownership and PCAL reset recovery, not microphone production tests.
